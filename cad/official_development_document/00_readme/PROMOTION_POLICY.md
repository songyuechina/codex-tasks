# Promotion Policy

本文件定义 `official_development_document` 第三轮后的晋升机制。

## 1. 为什么要有晋升机制

本体系不是静态教材，也不是一次性整理出来的 CHM 摘要。

它服务于真实 CAD 施工图自动化任务，因此必须随着真实使用不断调整重点：

- 真实任务会暴露新的关键对象
- 原本低频的对象可能突然卡住主链
- 某些属性 / 方法虽然出现次数不多，但一旦出问题就直接影响打印、布局、图签或目录

因此，本体系必须能从“反馈”走到“晋升”。

## 2. 对象的重要等级不是固定的

第一轮、第二轮给出的高频 / 低频判断，只是初始安排。

真正优先级的判断依据是：

- 真实任务是否反复使用
- 是否多次退回 `06_on_demand_index`
- 是否已经阻塞主链实现
- 是否需要单独的 pywin32 使用规则
- 是否已经出现项目实现路径

真实任务高于先验分级。

## 3. 何时触发晋升评估

满足任一条件都应触发评估：

- 某对象 / 方法最近多次出现在真实任务中
- 某对象虽然只出现一次，但直接卡住主链任务
- Codex 多次回退到原始 HTML 才找到信息
- 多个任务卡同时需要同一对象
- 该对象需要单独的 pywin32 规则
- 项目内已出现对应实现路径
- 该对象已经被记录为 `hotspot candidate`

## 4. 何时直接晋升为主干

以下情况可直接晋升：

- 影响打印结果正确性
- 影响布局 / 空间切换
- 影响图签 / 目录更新
- 影响块属性读取或写入
- 影响对象识别和选择
- 是项目已有稳定函数的核心依赖

## 5. 晋升后必须补齐哪些信息

至少补齐：

- `03_core_symbols/...` 对应核心符号卡
- 配套 `meta.json`
- 任务关联
- 必要的 pywin32 规则
- 项目实现路径
- 验证要求
- 来源追踪

## 6. 何时可以保持低频层

若对象：

- 只偶尔出现
- 与当前主链无关
- 还未造成实际阻塞
- 暂不值得投入较大整理成本

则继续保留在 `06_on_demand_index/`，只做轻量索引。

## 7. 执行闭环

当晋升评估被触发后，固定按下面的闭环执行：

1. 在 `07_validation/usage_feedback.jsonl` 记录真实任务反馈
2. 在 `07_validation/hotspot_candidates.json` 标记候选热点
3. 判断是继续观察还是直接晋升
4. 若直接晋升，补 `03_core_symbols/` 与必要规则文档
5. 回写 `04_task_cards/task_index.json`
6. 在 `07_validation/promotion_log.md` 记录晋升动作

## 8. 当前第三轮重点

当前优先围绕以下主链应用本机制：

- 布局打印
- 打印窗口控制
- 布局状态 / 系统变量联动
- 图签更新
- 目录生成
- 块属性读取 / 回写
