# PRINT_WORKFLOW.md

## 1. 接单入口

接到任务后，先确认：

1. 调度来源是项目总管还是人
2. 目标是打印还是打印信息分析
3. 输入是否完整
4. 当前是否已有可复用的权威结果
5. 当前任务是否已暴露脚本问题

若输入不完整，按 `PRINT_DISPATCH_PROTOCOL.md` 默认补全，不等待形成两套口径。

## 2. 任务分类

接到任务后，先判断任务属于哪一类：

### A. 普通打印任务

目标是输出 PDF。

默认流程：

1. 用 `basic` 构建打印计划
2. 执行打印
3. 校验结果
4. 输出 `print_summary.json`

### B. 放宽取区打印任务

只在 `basic` 无法覆盖真实区域、或用户明确要求时进入。

流程：

1. 用 `adaptive` 构建计划
2. 执行打印
3. 校验结果

### C. 净化适配打印任务

当 `adaptive` 产生伪打印区域时使用。

流程：

1. 用 `adaptive` 取区
2. 用 `print_area_content_analysis.py` 分析伪区域
3. 用 `print_area_scope_analysis.py` 判断是否存在伪极大打印范围
4. 若同时命中伪极大范围和伪区域风险，先按最大伪极大范围收束候选区域
5. 再过滤伪区域
6. 执行打印
7. 校验结果
8. 若出现空白 PDF，进入空白副本补救链

### D. 打印信息分析任务

目标不是打印，而是分析指定打印区域。

默认流程：

1. 若用户未指定模式，按 `basic` 取区
2. 确定待分析打印区域集合
3. 运行 `print_info_analysis.py`
4. 输出 JSON
5. 同步输出 Excel
6. 若用户需要按图纸信息重命名 PDF，则在最终 PDF 目录上运行 `print_pdf_naming.py`

若本次分析依附于一次真实打印任务，则默认应分析最终保留下来的打印区域集合，而不是已被净化或剔除的中间候选集合。

## 3. 打印信息分析标准流程

针对每个打印区域，按以下顺序分析：

1. 判断区域内是否存在内框线
2. 根据图纸方向寻找角点对齐图签块：
   - 横向：内框线右下角对齐块右下角
   - 竖向：按“旋转 `-90` 后的观察口径”处理，内框线左下角对齐块左下角
3. 将该块外包盒记为 `graphic_info_area`
4. 在 `graphic_info_area` 内用 `select_entities_in_window(...)` 选取对象
5. 仅保留文字对象：
   - `AcDbText`
   - `AcDbMText`
   - `TDbText`
   - `TDbMText`
6. 所有文字内容统一走 `cad_annotation.get_text_content()` 获取纯文本
7. 按固定优先级判定图纸名称 / 图纸编号：
   - `layer_named`
     若存在图层名包含 `图纸编号` 与 `图纸名称` 的文字，则直接按图层归类
   - `guide_rectangles`
     若角点对齐图签块内部可识别出两根 `Defpoints` 图层矩形多段线，且分别为红色与绿色：
     - 红色矩形映射为图纸名称区域
     - 绿色矩形映射为图纸编号区域
   - `fallback_regex`
     若前两者都失败，则按编号正则和最低 / 次低文字位置关系归类
8. 若图签块本身是属性块，属性字段作为补充信息保留；只有在标题 / 编号仍为空时才回退使用属性值
9. 输出结构化条目，并记录 `graphic_info_area_*` 与 `title_no_resolve_method`
10. 需要命名 PDF 副本时，默认命名规则为：
   - `sequence_no + project_name + subproject_name + drawing_title + drawing_no`
   - 各段之间用 `-` 连接
   - `drawing_no` 前可再加用户交代的编号前缀，例如 `JS-`
   - 若 `project_name`、`subproject_name` 或编号前缀为空，则直接跳过对应段

## 4. 打印信息分析稳定性要求

1. 单页分析前应尽量等待 CAD 进入 quiescent 状态
2. 单页分析遇到 COM busy / rejected 时，应先有限重试
3. 单页最终失败时，允许记入错误行，但不得让整个批次失败
4. 文本采样与判定逻辑一律收束到 `print_info_analysis.py`，不在其他脚本重复维护
5. PDF 命名副本只读取最终 `print_info_analysis.json` 与最终 PDF，不得再反向介入 CAD 分析
## 5. 输出组织规则

若只分析一个空间的一组打印区域：

- 主字典键使用排序编号：`01`、`02`、`03`...

若同时分析多个空间：

- 使用 `print_info_dict_by_space`
- 每个空间内部仍使用排序编号

兼容字段：

- 保留 `page_info_dict`

## 6. 验证规则

打印任务至少验证：

- 计划作业数
- 成功数 / 失败数
- 生成文件数
- 缺失文件数
- 零字节文件数
- 疑似空白 PDF 数
- `purified_adaptive` 时范围收束是否生效

打印信息分析至少验证：

- 分析区域总数
- `drawing_title` 覆盖数
- `drawing_no` 覆盖数
- `project_name` 覆盖数
- 内框线命中数
- 图签块命中数
- `title_no_resolve_method` 分布
- 是否存在 `analysis_error:*` 错误行

## 7. 自修复工作流

若执行过程中发现：

- 打印失败
- 计划错误
- 伪区域未被正确处理
- 打印信息分析明显误判
- 文档与代码不一致
- WPS 窗口持续堆积

则进入以下闭环：

1. 用当前真实案例复现问题
2. 定位问题属于哪条链、哪个脚本
3. 先做最小修补，不先扩张职责
4. 用同一案例重跑验证
5. 更新输出目录说明
6. 更新规则 / 流程 / 知识文档
7. 更新对话记录

## 8. 新案例迭代流程

遇到新案例后，不要只修脚本。

至少要同步完成：

1. 更新案例索引
2. 记录新结果目录
3. 把新经验写入知识文档
4. 若默认判断被改变，更新规则或工作流文档
