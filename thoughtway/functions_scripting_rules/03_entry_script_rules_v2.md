# 03_entry_script_rules.md

版本：V2.0

## 目标

规范入口脚本职责边界，使入口层负责：

- bootstrap
- 调试模式设置
- 参数解析
- 顶层调度
- 异常兜底
- 结果汇总

而不是把大量业务逻辑直接堆在入口脚本里。

## 入口脚本必须负责的事

1. 使用统一 bootstrap 模板
2. 调用 `set_debug_mode()` 设定运行模式
3. 解析参数 / 环境 / 路径
4. 调用系统层或业务层函数
5. 对顶层异常进行兜底记录
6. 明确返回成功/失败结果

## 入口脚本不应负责的事

- 大量具体业务实现
- 重复写底层工具函数
- 临时拼凑 CAD 连接逻辑
- 在入口层直接替代系统骨架模块

## 守护脚本也属于入口脚本

以下脚本虽然不是“业务入口”，但本质上也是入口脚本：

- `cad_command_monitor.py`
- `cad_dialog_killer.py`

因此守护脚本也应遵守：
- bootstrap 规则
- 顶层异常兜底
- 单实例控制
- 清晰的启动/退出路径

## 禁止行为

- 在入口脚本中重新实现整个系统层
- 在入口脚本中塞入大量难以复用的业务代码
- 不做异常兜底就直接裸跑高风险 CAD 操作
- 把守护脚本伪装成普通库模块使用
