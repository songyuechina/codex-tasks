# 函数测试规范（初版）
更新时间：2025-11-29

本规范用于约束 Codex 在 D:/codex-tasks 工作区内对 CAD 函数进行分析、建模、测试与记录的行为。所有函数测试必须同时满足：/jst 工作流、D:/codex-tasks/CAD文件操作示范.txt 的基础操作要求，以及本规范条款。后续如需扩展，只能在此文件上增补。

## 1. 前置引用
- 必须先阅读目标函数所在脚本（常见：cad/scripts/CAD_basic.py 或 CAD_file_operations.py），明确功能、返回值、输入参数与依赖。
- 进入 Python 环境前，执行：
  `python
  from CAD_basic import *
  from CAD_file_operations import *
  `
- /jst 要求的“七个基础范式”与 CAD 状态循环是所有测试的外层流程。
- 基础操作示例一律参考 D:/codex-tasks/CAD文件操作示范.txt，不得擅自删减。

## 2. 功能分析与测试输入设计
1. **参数分析**：写下每个参数的业务含义、可选值、默认值、类型限制。
2. **输入就绪**：根据参数组合规划测试集，包含：
   - 正常路径（最常用场景）。
   - 边界/极限值（如最小图幅、最小厚度等）。
   - 错误或异常路径（必须触发明确的错误提示）。
3. **DWG 准备**：
   - 在 cad/Functional_control/Functions_XXX/<函数名>/ 下建立专属目录；若包含多个函数，必须为每个函数建立子目录。
   - 依据测试集生成 DWG、块模板或参考文件，命名应体现用途（如 lock_mode_sample.dwg）。
   - 所有 DWG 创建/复制均通过脚本自动化完成，脚本需支持命令行参数（示例：python create_test_samples.py block layer).

## 3. CAD 运行与命令序列
1. 每次测试都按 /jst 的顺序执行：
   - cad_zt_oneb() ⇒ litz() ⇒（必要时 li()）⇒ 函数操作 ⇒ save_file()/close_file() ⇒ cad_zt_oneb()。
   - 若命令超时 >120s 或出现 RPC/Busy，立即 cad_zt_zero() 清场后重试。
2. 开/新文件时遵循 CAD文件操作示范.txt 流程：绘制最小探针、保存、关闭，确保桌面只有 1 个天正进程。
3. 所有测试脚本须显式调用 cad_zt_oneb()、litz()，并在内部实现 open_file/
ew_file 重试与清理逻辑，禁止依赖人工步骤。
4. 运行前后必须清理与该函数相关的 DWG，避免遗留未保存文件。

## 4. 结果记录与回滚
1. **日志**：在函数专属资料夹的 	ests/test_log.txt 中追加记录：时间 | 模式/参数 | 句柄/结果 | 备注。
2. **README**：同步更新该函数资料夹 README，列出当前脚本、样例、最新一次成功命令及得到的关键句柄。
3. **回滚**：若脚本在测试中修改了 DWG，完结后必须恢复初始模板（删除临时件并重新复制基准模板或重新运行样例生成脚本），确保下一次执行仍可复现。
4. **失败处理**：若测试失败，只能通过修改函数或测试资产来修复；修复后必须重新执行完整测试并记录新的结果，禁止以“未运行”或“手动验证”作为收尾语。

## 5. README 与命令行要求
- 每个函数资料夹的 `README.md` **开头** 必须直接列出可复制执行的命令行示例（含 `cd /d ... && python ...` 或 `cmd /c "..."` 等完整前置导航）。  
- 若存在多个测试案例（不同模式/流程），可以连续多行列出多条命令，顺序需与 README 其余描述一致。  
- 每条命令在写入 README 之前必须亲自运行验证其成功执行，并确保输出结果符合预期；验证完成后才能记录“最新测试”信息。  
- 命令所引用的脚本、DWG、JSON 等资源必须存在于该函数的专属资料夹或 README 中明确说明的位置，保证用户粘贴后即可重现。

## 6. 规范示例——select_print_areas_smart
1. **分析**：确认 mode, lm, layer_name, lock_layers, cha_Y 等参数，并拆解 block/layer/screen 三种模式。
2. **样例 DWG**：
   - python tests/create_test_samples.py block layer：自动生成 lock_mode_sample.dwg（含 ≥50 000 的块外包盒）与 layer_mode_sample.dwg（闭合/未闭合多段线）。
   - 脚本内部调用 insert_file_as_block + 块缩放 + open_file 重试，保证一次命令即可完成资产准备。
3. **测试命令**：
   - README 首段列出：  
     `python tests/create_test_samples.py block layer`  
     `python tests/run_tests.py block layer`
   - block 模式输出 2 个句柄 ['4DE','4DF']
   - layer 模式输出 2 个句柄 ['4B8','4B9']
4. **记录**：
   - 	ests/test_log.txt 追加上述句柄。
   - README 的“最近一次现场测试”段落注明命令、时间、结果。
5. **清理**：脚本运行完会自动 close_file("no_save") 并复位到 cad_zt_oneb()，保证桌面回到“天正+未保存 DWG”状态。

## 6. 执行与迭代
- 每次新增函数任务，必须先阅读本规范，再结合 CAD文件操作示范.txt 和 cad/即时对话.txt 制定计划。
- 若任务需要新条目（如新增命令行模板、更多验证步骤），请在完成测试后更新此规范，并在 AGENT.md 中同步引用新条款。
- 未能遵守本规范的测试视为无效，需要立即重做。
