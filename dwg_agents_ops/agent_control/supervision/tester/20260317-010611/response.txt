2. Test cases / execution  

### 用例 1：先判定候选块内是否有任何文字被采到
- 类型：半自动/日志核对  
- Setup：使用当前复杂案例中任一已命中的 `TQ1` 主图签候选块结果  
- Steps：  
  1. 查看该候选块输出里，是否存在块内文字对象采样结果（TEXT/MTEXT/ATTRIB，或等价文本项）。  
- Expected result：  
  - **若一个文字项都没有**：优先怀疑 **“文字采样缺失”** 或 **“嵌套块未展开”**。  
  - **若有文字项，但三字段仍为空**：优先转到“选区不对/命中块框”的验证。  

### 用例 2：若无文字，区分“采样缺失”还是“嵌套块未展开”
- 类型：半自动/结构核对  
- Setup：同一 `TQ1` 候选块  
- Steps：  
  2. 检查候选块内部是否只看到子块引用（INSERT）而看不到最终文字对象；确认是否存在 1 层或多层嵌套块。  
- Expected result：  
  - **若块内主要是子块引用，文字在子块里**：根因偏向 **“嵌套块未展开”**。  
  - **若块内本应有直接文字对象，但仍未采到**：根因偏向 **“文字采样缺失”**。  

### 用例 3：若有文字，验证是否选中了块框而非文字区
- 类型：半自动/人工核对  
- Setup：选择一个已命中 `TQ1` 且能看到部分文字采样信息的案例  
- Steps：  
  3. 对比“候选块范围/定位框”与实际图签文字分布，确认采样区域是否覆盖标题、图号、工程名所在区域，而不是仅覆盖外框、线框或空白区。  
- Expected result：  
  - **若采样区域主要落在块框/边框，未覆盖文字密集区**：根因偏向 **“选到的是块框不是文字区”**。  
  - **若区域覆盖了文字区但字段仍空**：说明更可能是字段抽取规则问题，但这超出本次三分法最小验证范围。  

### 用例 4：用单个失败样本做最小交叉确认
- 类型：人工 CAD 验证  
- Setup：任选 1 个失败 DWG  
- Steps：  
  4. 在 CAD 中人工点选该 `TQ1` 图签：确认文字是  
     - 直接文字，还是  
     - 属性文字/嵌套块中的文字，  
     并肉眼判断标题、图号、工程名是否位于当前命中区域内。  
- Expected result：  
  - 可一次性辅助确认三类原因中的哪一类最接近真实问题。
