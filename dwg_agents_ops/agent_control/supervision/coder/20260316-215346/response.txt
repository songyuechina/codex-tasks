1. Implementation focus

面向“建筑施工图打印区域”的候选框，补充一套**可编码、少而稳**的“伪打印区域内容复杂度”判定标准，用于识别这两类应排除的区域：

- **空白/近空白区域**
- **仅含简单几何图形 + 少量文字/说明框**的区域  
  典型如：
  - 只有一个矩形边框
  - 打印线型说明、图例小框
  - 少量注释文字 + 几条短线

核心目标不是精确理解图纸语义，而是建立一个**低风险候选过滤器**：  
当某区域复杂度显著低于同页其它打印区域时，将其标记为“伪打印区域候选”。

---

2. Proposed or completed changes

以下是建议落地的**最小可实现规则集**。不依赖复杂识别，只依赖对区域内实体的统计。

---

### A. 先定义可统计的基础特征

对每个打印区域 `R` 统计区域内实体，建议至少分为：

#### 1) 实体计数类
- `n_total`：总实体数
- `n_line`：直线数
- `n_poly`：多段线数
- `n_arc`：圆弧/圆/椭圆数
- `n_text`：TEXT/MTEXT 数
- `n_hatch`：填充数
- `n_dim`：标注数
- `n_block`：块参照数

#### 2) 几何覆盖类
- `bbox_area(R)`：打印区域面积
- `entity_bbox_union_area`：区域内各实体外包框并集面积的近似值  
  如果并集不好算，可先用“实体外包框面积总和裁剪上限”的近似版本
- `coverage_ratio = entity_bbox_union_area / bbox_area(R)`

作用：快速区分“几乎没内容”的区域。

#### 3) 长度/规模类
- `total_line_length`：线/弧/多段线总长度
- `avg_entity_size`：实体平均包围盒尺寸
- `text_char_count`：总字符数

#### 4) 结构复杂度类
- `non_axis_line_count`：非水平/非垂直直线数
- `short_entity_count`：短线/小图元数量
- `intersection_count_est`：线段相交估计数（可选，算不动可先不做）
- `vertex_count_total`：多段线总顶点数

这些特征都比较容易编码，且对“说明框 vs 正式图纸”有区分度。

---

### B. 定义“简单几何主导”的判定

先识别区域是否主要由简单边框构成。建议引入以下规则：

#### Rule B1：矩形边框主导
若满足以下任意情况，可视为“简单边框候选”：

- 区域内存在 1 个外接区域接近打印框大小的闭合矩形/四边形；
- 且除该矩形外，其它实体很少：
  - `n_total_excluding_border <= 5`  
  或
  - `coverage_ratio < 0.05`

说明：这能命中“第一张只是矩形图形”的情况。

#### Rule B2：说明框/图例框特征
若满足：
- `n_text > 0`
- 文本集中在少数位置，`text_char_count` 不高（如 `< 100`）
- 几何实体以水平/垂直线为主：
  - `non_axis_line_count / max(n_line,1) < 0.1`
- `n_dim == 0`，`n_hatch == 0`
- `vertex_count_total` 低，或 `total_line_length` 明显偏低

则可视为“说明框型候选”。

说明：打印线型说明框往往是“表格/框线 + 少量文字”，结构规则但内容不复杂。

---

### C. 定义“区域内容复杂度分数”

建议不要一开始上机器学习，直接做**加权分数**，少而稳。

#### 复杂度分数 `C(R)` 建议形式

```text
C(R) =
  w1 * norm(n_total)
+ w2 * norm(vertex_count_total)
+ w3 * norm(total_line_length)
+ w4 * norm(n_text)
+ w5 * norm(text_char_count)
+ w6 * norm(n_dim + n_hatch + n_block)
+ w7 * norm(non_axis_line_count)
+ w8 * norm(coverage_ratio)
```

其中：
- `norm(x)`：归一化，可用同页各打印区域的中位数/最大值归一
- 建议权重偏向结构复杂实体：
  - `w6`、`w2`、`w3`、`w8` 稍高
  - `w4`、`w5` 中等
  - `w7` 中等偏低

#### 更稳的做法：页内相对比较
绝对阈值容易受图纸风格影响，建议优先使用**同一张 DWG / 同一布局页内相对阈值**：

- 计算同页所有候选打印区域的 `C(R)`
- 求：
  - `median_C`
  - `max_C`

然后定义：

```text
relative_complexity = C(R) / max(max_C, eps)
```

若某区域：
- `relative_complexity < 0.2`
- 且 `C(R) < 0.35 * median_C`

则判为**低复杂度候选**。

这样能匹配用户提出的：“其它打印区域明显复杂，则可判为伪打印区域候选”。

---

### D. 加一个“空白/近空白”硬过滤

这是最稳的，建议优先级最高。

#### Rule D1：近空白区域
如果满足任一：
- `n_total == 0`
- `coverage_ratio < 0.01`
- `n_total <= 2` 且 `text_char_count < 10`
- `total_line_length < L_min`（按图纸单位给阈值；若单位不明，优先不用绝对长度）

则直接标记为**伪打印区域**。

这条规则几乎无争议。

---

### E. 定义“伪打印区域候选”最终判定逻辑

建议分两级：

#### 一级：直接排除
满足以下任一：
1. 近空白
2. 单一大矩形边框 + 极少其它内容
3. 复杂度极低，且同页存在明显更复杂区域

则：
- `pseudo_print_candidate = true`

#### 二级：保守候选
如果只是“说明框倾向”，但还不够确定：
- 输出 `pseudo_print_suspect = true`
- 交给后续规则或人工复核

这样比一次性硬判更稳。

---

### F. 推荐的最小阈值集合

如果现在就要编码，我建议先用这组**保守默认值**：

#### 基础阈值
- `coverage_ratio < 0.01` → 近空白
- `n_total <= 3 and text_char_count < 20` → 极低内容
- `n_dim == 0 and n_hatch == 0 and n_block == 0` → 缺少正式图纸常见复杂元素
- `non_axis_line_count / max(n_line,1) < 0.1` → 框表型结构
- `text_char_count < 100` → 少量说明文本

#### 相对复杂度阈值
- `relative_complexity < 0.2`
- 且 `C(R) < 0.35 * median_C`

#### 边框型阈值
- 检出一个占打印区域大部分面积的矩形边框
- 其余实体数 `<= 5`

---

### G. 建议的实现顺序

为了“少而稳”，建议按下面顺序分阶段落地：

#### Phase 1：先上最稳规则
1. 近空白判定
2. 单一矩形边框判定
3. 页内相对复杂度比较

这三条已经能覆盖大部分“假打印区域”。

#### Phase 2：再补说明框识别
增加：
- 轴对齐线占比
- 少量文本
- 无标注/无填充/无块
- 顶点数低

#### Phase 3：必要时再补强
- 实体相交密度
- 文本分布离散度
- 连通分量数
- 表格/图例结构识别

---

### H. 建议输出字段

为了便于排查，建议规则引擎输出原因，不只给布尔值：

```json
{
  "pseudo_print_candidate": true,
  "score": 0.12,
  "relative_complexity": 0.08,
  "reasons": [
    "low_coverage",
    "single_border_rect",
    "much_simpler_than_peer_regions"
  ]
}
```

这样后续调参更容易。

---

### I. 为什么这套规则稳

因为它不依赖难做的语义识别，而是利用了施工图与说明框的稳定差异：

- 正式图纸通常：
  - 实体更多
  - 顶点更多
  - 线总长度更大
  - 结构更杂
  - 常伴随标注、块、填充、复杂轮廓

- 伪打印区域通常：
  - 覆盖率低
  - 只有边框
  - 只有少量文字
  - 线条规则、轴对齐
  - 相比同页其它区域显著简单

这与当前案例描述是吻合的。

3. Risks / blockers

1. **缺少现有代码接口细节**  
   任务包没有提供 `cad/system`、`cad/library`、`dwg_system_tools`、`dwg_cases` 中可复用的数据结构、实体访问 API、现有区域检测流程，因此我只能给出**可直接编码的规则设计**，不能准确指出应修改的具体模块和函数名。

2. **图纸单位/尺度不明**  
   若使用绝对长度阈值（如 `total_line_length < L_min`），会受单位影响。  
   最安全做法是优先使用**页内相对比较**，少用绝对阈值。

3. **块参照展开能力未知**  
   若大量图元封装在 block 中，而系统当前只能看到 block reference 数，复杂度可能被低估。  
   保守方案：先把 `n_block` 本身作为复杂度加分项。

4. **覆盖率计算实现成本不明**  
   `entity_bbox_union_area` 若精算较重，可先用近似法：
   - 实体包围盒面积求和后裁剪
   - 或直接用“有内容网格占用率”近似  
   先求稳，再优化。

5. **说明框与小样图可能混淆**  
   某些小比例详图也可能复杂度低。  
   因此建议把“低复杂度”定义为**伪打印候选**，并结合“同页对比显著更简单”再硬判。
