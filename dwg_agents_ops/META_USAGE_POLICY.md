# META_USAGE_POLICY --- 智能体使用 Meta 的统一策略（补丁版：复杂返回分支降级）

> 目标：让智能体 **优先使用 quote.meta.json 快速完成任务**，
> 仅在必要时升级阅读 procedure 或源码，避免不必要的复杂分析。
> 本版本新增：**当返回分支过复杂/不可信时的固定降级处理**，防止智能体"猜测调用方式"。

适用范围：D:/codex-tasks 全项目

------------------------------------------------------------------------

# 1. 默认模式（Fast Mode）

智能体在处理脚本时：

1.  只读取：
    -   `A_quote.meta.json`
2.  不主动读取：
    -   `A_procedure.meta.json`
    -   `A.py` 源码

满足以下条件即可直接执行：

-   public_api 清晰
-   参数与返回结构明确
-   副作用/约束已写明
-   无明显不确定性标记（如大量 todo 或 low confidence）

------------------------------------------------------------------------

# 2. 最小自检规则（必须执行）

调用函数后必须进行基本校验：

-   ret 是 dict（或 meta 声明的返回类型）
-   ret\["ok"\] == True（若返回结构包含 ok）
-   返回结构存在预期字段（如 counts_by_space / counts_by_type）
-   errors 为空（若包含 errors 字段）
-   数据规模/类型数量合理（非负、非空、逻辑一致）

若自检通过 → 任务完成。

------------------------------------------------------------------------

# 3. 升级条件（Upgrade Trigger）

出现以下任意情况，升级阅读：

-   ok == False
-   errors 非空
-   关键字段缺失
-   统计口径明显不符
-   性能异常
-   与人工对比差异明显
-   quote 中存在 high todo 或 complex_control_flow

升级顺序：

1️⃣ 读取 `A_procedure.meta.json`\
2️⃣ 若仍无法定位 → 阅读 `A.py` 源码（仅相关函数块）

------------------------------------------------------------------------

# 4. 复杂返回分支的固定降级处理（新增，硬规则）

当出现以下任意一种信号时，**视为 quote 中 returns 信息不可信**：

-   quote.functions\[\].confidence.returns == "low"
-   quote.functions\[\].returns\[\].condition == "complex_control_flow"
-   quote.quality.todo 包含 return/branch/condition not verified 等提示
-   quote 对返回结构描述不完整或与实测不一致

此时智能体必须遵循：

## 4.1 不猜测（硬禁止）

-   不猜字段名
-   不猜返回结构
-   不在未自检通过的情况下继续下游决策

## 4.2 先调用 + 自检（保底）

-   允许先按 signature 调用一次
-   但必须立刻执行最小自检
-   自检失败 → 立即升级到 procedure

## 4.3 只用"二分法"理解返回（推荐做法）

在无法可靠细分分支时：

-   只区分：success / error
-   success：返回 dict，包含最小关键字段（以 procedure 或源码确认）
-   error：返回 dict，包含 ok=False / errors（以 procedure 或源码确认）

------------------------------------------------------------------------

# 5. 读取源码规则（Slow Mode）

读取源码时：

-   只定位 public_api 函数
-   只阅读相关内部函数（最多 3 层调用链）
-   不对整文件做无意义扫描

目标：

-   确认真实返回结构（字段名/必选字段）
-   确认正确调用方式（参数组合/资源边界）
-   修复流程骨架（不追求逐行重构所有 helper）

------------------------------------------------------------------------

# 6. 重构原则

若需重构函数：

-   以 procedure.workflow 为骨架
-   保持 public_api 不变（除非明确需要改动）
-   保留资源边界（文件打开/关闭/数据库写入）
-   保持统计口径一致（如 Model + Layout.Block）

------------------------------------------------------------------------

# 7. 禁止事项

-   默认直接阅读源码（跳过 quote）
-   在未自检情况下盲目修改
-   因为复杂控制流而无限细化 meta
-   修改 public_api 却未同步更新 quote.meta.json

------------------------------------------------------------------------

# 8. 判定标准

若仅通过 quote 即可正确调用并完成任务 → 成功。\
若升级到 procedure 仍可快速定位 → 合格。\
若必须全文件阅读才能理解 → meta 不达标，应优化（优先补齐 public_api
的二分法 returns 与关键字段）。

------------------------------------------------------------------------
